## [MemGPT](https://arxiv.org/pdf/2310.08560)


+-------------------------------------------------------------------+
|                        LLM Context Window                         |
|  +---------------------+-----------------------+---------------+  |
|  | System Instructions |    Working Context    |  FIFO Queue   |  |
|  |      (Static)       |      (Read/Write)     |  (Read/Write) |  |
|  +---------------------+-----------------------+---------------+  |
|                            MAIN CONTEXT                           |
+-------------------------------------------------------------------+
                                  ^
                                  |  (via Function Calls / Queue Manager)
                                  v
+-------------------------------------------------------------------+
|                          EXTERNAL CONTEXT                         |
|  +-----------------------------------+-------------------------+  |
|  |           Archival Storage        |      Recall Storage     |  |
|  |   (Vector Database/Knowledge)     |   (Message DB/History)  |  |
|  +-----------------------------------+-------------------------+  |
+-------------------------------------------------------------------+

上下文:
- 主上下文(main context)类似内存
  + system instructions   静态只读的，包含MemGPT控制流，不同内存层级的预期用途和如何使用MemGPT函数(tool_use description)
  + working context 固定大小的非结构化文本读写块，仅能通过MemGPT函数调用写入。在对话场景中，工作上下文旨在用于存储有关用户和 Agent 所扮演人设的关键事实、偏好及其他重要信息，从而使 Agent 能够与用户顺畅对话。
  + FIFO Queue 储存流转的对话历史消息，包括agent与用户之间的消息，系统消息(比如内存警告)，函数调用的输入与输出
- 外部上下文(external context)类似磁盘
  + Recall Storage 完整历史日志数据库，顺序记录agent经历过的所有原始消息和对话
  + archival storage 储存长文本，资料和不需要频繁放入working context的深度记忆
- 主上下文和外部上下文可以page-out / page-in

队列管理器(Queue Manager)：
管理回溯储存(recall storage)和FIFO队列中的消息。当系统收到一条新消息时，队列管理器会将传入的消息附加到 FIFO 队列末尾，拼接 prompt token，并触发 LLM 推理以生成 LLM 输出（即 completion token）。队列管理器会将传入的消息和生成的 LLM 输出同时写入回溯存储（即 MemGPT 消息数据库）。当通过 MemGPT 函数调用检索回溯存储中的消息时，队列管理器会将它们附加到队列尾部，以将其重新插入到 LLM 的上下文窗口中。
